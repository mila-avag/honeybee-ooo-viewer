Instructions

Each tab says what it reads, the order it decides in, and what it leaves out. The same explanation sits on the tab itself, next to the button.

What you need

Link check and Merge files never call Redash. The CSV stays in this browser. A delivery file can be multiple GB because of debug_info columns. Link check reads the file in a stream and keeps only the id, the two names, and the two links.

Build CSV, Load saved result, and Recompute run on the hosted app. Redash access is configured on that server. This page never receives it. The purple header says “Redash: connected” when those buttons can run. Link check, Merge files, and Download query work even when it does not.

Download query fetches the SQL file that sits next to this page and saves it. It does not run Snowflake. Task upload is data source 30, the same source as saved query 400607. The download fills in the task ids you pasted. It does not edit query 400607. Batch progress and Ultra deliveries are data source 22. Ultra deliveries is saved query 390037.

Load saved result returns the last finished warehouse run. That is a read of a stored result, usually under a second. Recompute runs the SQL again and replaces that stored result. On this project that scan is about 10 minutes. Use Recompute when the queue has moved and the saved time in the status line is too old.

Link check

When. You have a delivery sheet and need to confirm each model’s link matches the model name.

Need. A delivery CSV. The file can be multiple GB. Only the task id, model names, and links are kept.

You get. Task id, model A and B names and links, and a flag for each side. Problems only is on by default. Download CSV keeps every row.

The flag is decided in this order, and the first match wins. A later rule never gets a chance to override an earlier one.

  • An empty name produces a blank flag. The row still shows under Problems only, because a blank flag is not OK.
  • A name with an empty link is MISSING LINK.
  • A link whose text starts with [No trajectory link is NO LINK AVAILABLE. That is a filled-in placeholder, so it is a different failure from a blank cell.
  • A name containing gpt must start with https://chatgpt.com/s. That covers both /s/ and /share/. chatgpt.com/c is WRONG LINK.
  • Otherwise a name containing claude or fable must start with https://claude.ai/share/.
  • Otherwise a name containing argon must start with https://scale-cds-public-us-west-2.s3.amazonaws.com/. Argon is checked before Gemini so “Gemini Argon” is an Argon link.
  • Otherwise a name containing gemini must start with https://share.gemini.google/. gemini.google.com is WRONG LINK.
  • A name that matches none of those classes is WRONG LINK, including N/A, even when the URL itself looks fine.

Merge files

When. The same tasks are split across two or more CSVs and you want one row per task.

Need. Two or more CSVs, dropped in the order they should apply. Each file needs a task id column (task_id or task).

The merge walks the files from top to bottom. For each row it reads task_id or task. A row with neither is counted and skipped. The first time an id appears, that row is stored. A later row with the same id copies every column from the later file onto the stored row, including a blank cell. A blank in the later file replaces a filled cell from the earlier file. A column that exists only in a later file is added. A single cell over 256 KB is stored as empty so a debug_info blob cannot freeze the browser.

Task upload

When. You have a list of task ids and need the upload CSV for them.

Need. A Model pairs count, a Model A and Model B name for each pair, a credential mode (single or dual), and the task ids. The Redash server, unless you use Download query and run the SQL on data source 30. For logins, export the test accounts sheet as a CSV with Accounts and Password columns. If you need more demo accounts, reach out to @kevin chen.

You get. honeybee_task_upload.csv. The columns stay model_a_name and model_b_name. Choosing 3 pairs writes 3 rows for every task: row 1 is Model A 1 vs Model B 1, row 2 is Model A 2 vs Model B 2, and so on. Language is en_US on every row. Up to 5,000 ids. Demo logins are filled from the accounts file: the two logins on a row are different accounts, and emails are repeated as little as possible. Accounts stay in the browser and are written only into the CSV you download.

After the rows come back, the page checks each one. A list counts as empty when the cell is blank, null, [], {}, or a JSON list whose items have no title and no id. A list with one real criterion counts as present.

  • Every task needs a non-blank opening_prompt.
  • Every task needs at least one target_deliverables entry.
  • Every task needs at least one rubric_criteria entry.
  • If task_type contains “aspirational”, universe must be non-blank. Any other task type may have an empty universe.
  • environment_context and estimated_turns are allowed to be empty. They are never flagged.

A broken row is still in the CSV. Broken rows are moved to the end, and the page lists the task id, the task type, and the missing fields. Ids that Snowflake did not return are listed separately. They have no row to put in the file. The download is not blocked.

The credential dropdown writes the word single or dual into credential_mode. It does not change how many logins are filled. When an accounts file is loaded, every output row gets two different logins. The assignment looks at the whole file, including every model pair. It gives as many rows as possible a login that appears on no other row. A login used on pair 1 is already spent, so pair 2 of the same task does not count it as unused. Spare logins are the ones that get repeated. Passwords are written only into the CSV you download. They are not sent to Redash.

Batch progress

When. You want the current count of open tasks by model pair and review layer.

Need. The Redash server. Load saved result returns the last run. Recompute scans the project and takes about 10 minutes. Download query saves the SQL for data source 22.

The layer is the latest human node by created_at, the same read as Ultra deliveries. If that node is pending, the task is counted at its level, including L-1 tasks that nobody has attempted yet. Model A and Model B are the task metadata names, with the same renames as the deliveries query. Model A and Model B are multi-select filters on the loaded table. Columns can be hidden. A column header sorts the table. A layer with no tasks is left out.

Ultra deliveries

When. You want the delivery pivot: what went out recently, what is still in review, and what is still in attempt, by model pair.

Need. The Redash server. Load saved result returns the last run. Recompute takes about 10 minutes. Download query saves the SQL for data source 22.

The window defaults to 60 days. The Lookback menu is in weeks, plus the 60-day choice. Changing it does not rerun Snowflake until you load or recompute. The first run for a window takes about 10 minutes. Later loads of that same window use the saved result. Model A and Model B are multi-select filters on the loaded table. Columns can be hidden. A column header sorts the table. The window is Pacific time.

  • Delivered. Sent in a delivery batch inside the selected window, or completed in that window and never present in any sent batch.
  • Pending review (L8, L10, L12). The latest human node by created_at is pending at one of those three levels.
  • Delivered + pending review. Those two counts added together.
  • Still in attempt. The latest human node by created_at is pending at -1. Tasks with no attempt yet are included. Batch progress counts this same set as L-1.
  • Model A minutes per task. Average of all time spent on tasks for that model A. The same number repeats on every row for that model A, because it is a property of model A, not of the pair.
  • Pair minutes per task. Average time spent on tasks in this model A and model B pair.
  • Total tasks. Delivered, plus pending review, plus still in attempt. The Total row at the bottom sums this column only. The other columns are left blank on that row so a sum of averages is not presented as a real total.
